# Лабораторная работа №2 — Потоковый анализатор файлов

## Описание проекта

**StreamStats** — консольное приложение на Python для потокового анализа событий из файлов форматов CSV и JSONL.

Программа читает события, проверяет корректность их данных, собирает статистику и сохраняет итоговый отчёт в формате JSON.

При обработке используются генераторы (`yield`), благодаря чему события обрабатываются последовательно, без загрузки всего файла в оперативную память.

## Возможности

- Чтение файлов форматов CSV и JSONL.
- Обработка нескольких входных файлов за один запуск.
- Проверка корректности событий.
- Проверка временных меток в формате ISO 8601.
- Подсчёт общего количества событий.
- Подсчёт событий по уровням логирования и источникам.
- Определение пяти источников с наибольшим количеством событий ERROR и CRITICAL.
- Определение самой ранней и самой поздней временной метки.
- Пропуск некорректных событий с помощью `--skip-invalid`.
- Подсчёт количества пропущенных событий.
- Сохранение статистики в JSON-файл.
- Обработка ошибок с использованием собственных классов исключений.

## Форматы входных данных

Каждое событие содержит четыре обязательных поля:

| Поле | Описание |
|---|---|
| `timestamp` | Временная метка в формате ISO 8601 |
| `level` | Уровень события |
| `source` | Источник события |
| `message` | Текст сообщения |

Допустимые уровни событий:

`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`.

### Пример CSV

Файл `events.csv`:

```csv
timestamp,level,source,message
2026-10-14T10:00:00,INFO,auth,User logged in
2026-10-14T10:05:00,ERROR,db,Connection failed
2026-10-14T10:10:00,WARNING,auth,Invalid password
```

### Пример JSONL

Файл `events.jsonl`:

```jsonl
{"timestamp":"2026-10-14T10:00:00","level":"INFO","source":"auth","message":"User logged in"}
{"timestamp":"2026-10-14T10:05:00","level":"ERROR","source":"db","message":"Connection failed"}
{"timestamp":"2026-10-14T10:10:00","level":"WARNING","source":"auth","message":"Invalid password"}
```

В формате JSONL каждая строка содержит отдельный JSON-объект.

## Использование

### Анализ CSV-файла

```bash
poetry run python -m streamstats analyze events.csv --format csv --output report.json
```

### Анализ JSONL-файла

```bash
poetry run python -m streamstats analyze events.jsonl --format jsonl --output report.json
```

### Анализ нескольких файлов

```bash
poetry run python -m streamstats analyze events1.csv events2.csv --format csv --output report.json
```

События из всех переданных файлов учитываются в общей статистике.

Все входные файлы одного запуска обрабатываются в формате, указанном через `--format`.

### Пропуск некорректных событий

```bash
poetry run python -m streamstats analyze events.csv --format csv --output report.json --skip-invalid
```

При использовании `--skip-invalid` некорректные события пропускаются, а их количество учитывается в итоговом отчёте.

Без этого параметра при обнаружении некорректного события программа выводит сообщение об ошибке и завершает работу с кодом `2`.

### Параметры командной строки

| Параметр | Описание |
|---|---|
| `INPUT` | Один или несколько входных файлов |
| `--format` | Формат входных файлов: `csv` или `jsonl` |
| `--output` | Путь для сохранения JSON-отчёта |
| `--skip-invalid` | Пропуск некорректных событий |

## Формат итогового отчёта

Пример отчёта для приведённых выше трёх событий:

```json
{
    "total_events": 3,
    "by_level": {
        "INFO": 1,
        "ERROR": 1,
        "WARNING": 1
    },
    "by_source": {
        "auth": 2,
        "db": 1
    },
    "top_error_sources": {
        "db": 1
    },
    "earliest_timestamp": "2026-10-14T10:00:00",
    "latest_timestamp": "2026-10-14T10:10:00",
    "skipped_events": 0
}
```

### Описание полей отчёта

- `total_events` — общее количество корректных событий.
- `by_level` — количество событий каждого уровня.
- `by_source` — количество событий по источникам.
- `top_error_sources` — до пяти источников с наибольшим количеством событий ERROR и CRITICAL.
- `earliest_timestamp` — самая ранняя временная метка.
- `latest_timestamp` — самая поздняя временная метка.
- `skipped_events` — количество пропущенных некорректных событий.

Для пустых входных файлов количество событий равно нулю, а временные метки принимают значение `null`.

## Обработка ошибок

В проекте определены собственные классы исключений:

| Исключение | Назначение |
|---|---|
| `StreamStatsError` | Базовое исключение приложения |
| `InvalidFormatError` | Неподдерживаемый формат файла |
| `InvalidEventError` | Некорректные данные события |
| `InvalidTimestampError` | Некорректная временная метка |
| `CLIConfigError` | Ошибка конфигурации командной строки |

Программа также обрабатывает ошибки доступа к файлам и проверяет, что входной и выходной пути не совпадают, чтобы предотвратить случайную перезапись исходных данных.

## Особенности реализации

Потоковая обработка. Парсеры используют yield, поэтому события передаются на обработку по одному, а не накапливаются в списке.

Разделение ответственности. Чтение файлов, проверка событий, сбор статистики и сохранение отчёта реализованы в отдельных модулях.

Обработка ошибок. Для разных видов некорректных данных используются отдельные классы исключений.

Тестируемость. Основные компоненты приложения проверяются автоматическими тестами.
